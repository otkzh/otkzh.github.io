# 開発方針

この文書は、`otkzh.github.io`を今後更新するときの判断基準をまとめたものです。個別のCSSやJavaScriptの実装方法は[技術TIPS](./technical-tips.md)、文字サイズの具体的な基準は[文字サイズと可読性の基準](./typography.md)を参照してください。

## サイトの目的

- 太田一穂の人物像、活動、記録へ短時間で到達できるデジタル名刺とする
- 地図、オープンデータ、シビックテック、教育、Podcastなど複数の活動を、過度に説明的にならず伝える
- GitHub Pagesで安定して配信できる静的サイトを維持する
- 一時的な演出よりも、実機での読みやすさと操作の確実さを優先する

## 情報設計

トップページは、表裏に見える3ページ構成のカードとして扱います。

1. プロフィール: 名前、キャッチコピー、肩書き
2. 活動: 活動領域と具体的な団体・成果へのリンク
3. Memo: 記事の導入と主要記事へのリンク

メールとSNSは特定のページに所属させず、全ページ共通のフッターに置きます。団体リンクは活動ページ、記事リンクはMemoページに限定し、リンクの目的が混ざらないようにします。

`/redirect/`はGitHub Pages上の静的な入口として維持し、`/?card=activity`を表示する用途に使います。

## レスポンシブ方針

- スマートフォン版を縮小したPC版、またはPC版を詰め込んだスマートフォン版にはしない
- 掲載内容とページ構成は全画面サイズで共通にする
- スマートフォン縦位置では、縦型名刺が安全領域を除く画面の大部分を占める構成にする
- スマートフォン横位置とPCでは、91:54の横型名刺を基本比率とする
- 横位置は幅だけでなく`orientation`、高さ、アスペクト比を見て調整する
- 特にブラウザUIで高さが減りやすい横長スマートフォンを先に検証する
- ノッチやジェスチャー領域は`safe-area-inset-*`を使って避ける

## デザイン方針

- 紙の名刺らしい罫線、見当、余白と、デジタルらしいページ切り替えを組み合わせる
- 白、黒、青を基本色とし、色は情報階層と操作状態を示すために使う
- 縦位置はゴシック、横位置は明朝を中心にして、端末の向きによる変化を出す
- フッターは後付けの操作パネルではなく、名刺の連絡先欄として各面のデザインに統合する
- プロフィール面、活動面、Memo面でフッターの配色や地模様を変えて、現在位置を補助する
- アイコンだけのリンクには、視覚上のラベルに加えて`aria-label`と`title`で宛先を明示する

## 可読性とアクセシビリティ

- 本文、補助文字、リンクの最小サイズは[文字サイズと可読性の基準](./typography.md)に従う
- 名前、見出し、キャッチコピーの改行位置を意図的に管理する
- リンクとボタンには、スマートフォンで押しやすいタップ領域を確保する
- キーボードの左右キーでもページを移動できるようにする
- 非表示ページのリンクはタブ移動の対象から外す
- `prefers-reduced-motion`では不要な動きを止める
- ピンチズームを禁止しない
- 色だけに依存せず、罫線、番号、位置でも状態を表す

## インタラクション方針

- 右半分のタップは次ページ、左半分のタップは前ページとする
- 左右スワイプとキーボード操作も同じ方向規則にそろえる
- ページはプロフィール、活動、Memoの順で循環する
- リンクをタップしたときはページを切り替えない
- ページ切り替えはURLの`card`クエリにも反映し、特定ページを直接共有できるようにする
- 端末の傾きはレイアウトやカード全体の座標を変更せず、反射、影、縁などの装飾だけに使う
- センサーが使えない端末でも、同じ情報と操作を提供する

## 安定性の優先順位

次の順で品質を判断します。

1. 実機で画面外へはみ出さず、情報とリンクを利用できる
2. 文字が読みやすく、タップやスクロールを誤認しない
3. URL共有、キーボード、センサー非対応時にも機能する
4. アニメーションや傾きによる演出が自然に見える

3D演出がモバイルブラウザのviewportや描画領域へ影響する場合は、演出を弱めるか削除します。機種固有の不具合を「端末側の問題」として扱わず、再現条件を狭めて安全なフォールバックを用意します。

## コンテンツ方針

- 名前、肩書き、連絡先などの一次情報は名刺や本人提供情報を基準にする
- 活動内容を説明するときは、抽象語だけでなく具体的な団体・成果へリンクする
- 外部リンクはリンク先が分かる文言またはアクセシブルな名前を付ける
- Memoはトップページのカードデザインと統一しつつ、本文を読むためのスクロールを妨げない
- 診断ツール、EXIFツールはサイトの対象外とし、再追加には目的と保守方針の確認を必要とする

## 開発フロー

- 作業は最新の`master`から`codex/`接頭辞のブランチを作って行う
- 既存の未コミット変更は利用者の変更として扱い、関係のない差分を触らない
- コミットは変更目的ごとに分け、簡潔な日本語のコメントを付ける
- 最低限`npm run check`と`npm run build`を成功させる
- 表示変更は縦型スマートフォン、超横長スマートフォン、PCで確認する
- モバイル固有の操作変更は、可能な限りタップ中と完了後のviewportも計測する
- push後に`master`向けのPRを作り、競合とCIの状態を確認する

## 完了条件

- 要求された情報・操作が対象画面に反映されている
- 主要な画面サイズで文字切れ、横スクロール、固定フッターとの重なりがない
- 外部リンク、メールリンク、ページ切り替えが互いに干渉しない
- Astroの型チェックと静的ビルドが成功する
- ブランチ、コミット、PRの状態が利用者へ共有されている

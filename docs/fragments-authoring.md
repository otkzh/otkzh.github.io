# Fragmentsの記事を書く

Fragmentsは「思考の断片」。考えたこと、調べたこと、途中のメモ、活動記録や開発の意図を残す場所です。`src/content/fragments/`へMarkdownを追加すると、`/fragments/`の一覧に日時の新しい順で表示されます。

## 必須のメタデータ

```yaml
---
title: 記事のタイトル
date: "2026-10-06T08:00:00+09:00"
tags: ["Web", "Structure", "Human"]
summary: 何について書いた記事か、読む前にわかる1〜2文。
---
```

本文はこのあとに書きます。タイトル・日時・サマリーはページが表示するので、本文に同じh1見出しを重ねる必要はありません。本文の見出しは`##`から始めます。記事名・日時・サマリー・タグの欠落や不正な日時はビルド時にエラーになります。

日時は日本時間のオフセット`+09:00`付きで、引用符で囲みます。過去の記事に日付しかない場合は、その日付を保ち、時刻を推測して補いません。旧記事4本の日時はGitの最初の記録から補い、`dateSource: git-first-record`を付けて由来を記事内に表示しています。

### 書き手のタグ

`tags`には、話題のタグに加えて書き手を示すタグを1つだけ必ず入れます。

- `Human`：本人が書いた記事。一覧の左端に細い琥珀色の線が付き、「Humanだけ見る」から絞り込める
- `AI`：AIで生成した文章の記事。開発の記録をAIとの作業でまとめた場合もこちら。AIそのものを話題にする記事には、別に`GenerativeAI`などの話題のタグを付ける

どちらもない、または両方あるとビルド時にエラーになります。本文は本人が書き、要約（`summary`）だけAIで付けた場合は`summarySource: ai`も付けます。

```yaml
tags: ["Maps", "OpenData", "Human"]
summarySource: ai
```

### 話題のタグ

各記事に内容に合う英語のタグを1つ以上付けます（例: Maps、Mobile、VibeCoding）。一覧の「Tags」をタップすると絞り込み一覧が開きます。一覧と本文のタグから同じテーマの記事へ進めます。タグ別一覧も新しい順に10件ずつ表示します。サマリーは言い切りの「だ・である」調（「〜する」「〜である」など）で統一します。一覧は新しい順に10件ずつ表示し、2ページ目以降は`/fragments/page/2/`のようなURLになります。

## 開発の記録に残すこと

- 何が気になったのか、どんな読み方や使い方をしてほしかったのか
- 何を選び、どう変えたのか。試して見直したことがあれば、その理由
- ローカルで確認したこと、まだ確かめられていないこと

操作の実況や変更ファイルの羅列より、訪れた人にとって何が変わるかを書きます。過去の記事は当時の記録として残し、判断が変わったらその理由を新しい記事にします。同じ目的の調整中は、同じ記事を整えて構いません。

## ローカル確認と公開

`npm run check`と`npm run build`を実行し、`npm run dev`で一覧、本文、前後の移動を確かめます。スマートフォンの縦・横とPCで、日時・タイトル・サマリーが読めることと横方向のはみ出しを確認します。

利用者に確認結果を共有してから、明示的に依頼された場合だけコミットします。pushやPR更新も自動では行いません。

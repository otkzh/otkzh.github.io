# noteの記事を書く

noteは、考えたことと開発の意図を残す場所です。`src/content/note/`へMarkdownを追加すると、`/note/`の一覧に日時の新しい順で表示されます。

## 必須のメタデータ

```yaml
---
title: 記事のタイトル
date: "2026-10-06T08:00:00+09:00"
summary: 何について書いた記事か、読む前にわかる1〜2文。
---
```

本文はこのあとに書きます。タイトル・日時・サマリーはページが表示するので、本文に同じh1見出しを重ねる必要はありません。本文の見出しは`##`から始めます。記事名・日時・サマリーの欠落や不正な日時はビルド時にエラーになります。

日時は日本時間のオフセット`+09:00`付きで、引用符で囲みます。過去の記事に日付しかない場合は、その日付を保ち、時刻を推測して補いません。旧記事4本の日時はGitの最初の記録から補い、`dateSource: git-first-record`を付けて由来を記事内に表示しています。

カテゴリによる分類は表示せず、記事の内容はタイトルとサマリーで伝えます。

## 開発の記録に残すこと

- 何が気になったのか、どんな読み方や使い方をしてほしかったのか
- 何を選び、どう変えたのか。試して見直したことがあれば、その理由
- ローカルで確認したこと、まだ確かめられていないこと

操作の実況や変更ファイルの羅列より、訪れた人にとって何が変わるかを書きます。過去の記事は当時の記録として残し、判断が変わったらその理由を新しい記事にします。同じ目的の調整中は、同じ記事を整えて構いません。

## ローカル確認と公開

`npm run check`と`npm run build`を実行し、`npm run dev`で一覧、本文、前後の移動を確かめます。スマートフォンの縦・横とPCで、日時・タイトル・サマリーが読めることと横方向のはみ出しを確認します。

利用者に確認結果を共有してから、明示的に依頼された場合だけコミットします。pushやPR更新も自動では行いません。
